# 基于 DeBERTa 的临床病历证据抽取

这是一个临床自然语言处理项目：给定一段医学生撰写的患者病历和一条临床评分要点，模型自动定位病历中支持该要点的文本片段，并输出对应的字符位置。

项目以团队课程作业形式完成，围绕**标注数据有限、临床表达多样、文本边界难以精确定位**等问题，探索了从数据处理、模型训练到交叉验证和消融分析的完整流程。

**技术栈：** Python · PyTorch · Hugging Face Transformers · DeBERTa · scikit-learn · Weights & Biases

## 项目背景

在临床技能训练中，医学生需要根据标准化病人提供的信息撰写患者病历。评分人员随后对照评分量表，判断病历是否覆盖了关键症状、病史和生活方式等临床要点。

这一过程难以直接通过关键词匹配自动化：同一个临床概念可能有多种表述。例如，“食欲下降”可能被写成“吃得更少”或“没有胃口”。因此，系统需要理解评分要点与病历文本之间的关系，同时找出支持该判断的具体证据。

本项目将任务建模为**基于临床要点的文本跨度抽取**：

- **输入：** 一段患者病历和一条临床评分要点。
- **输出：** 病历中表达该要点的一个或多个文本片段的字符区间。
- **评估指标：** 字符级 micro-averaged F1。

项目任务来源于 Kaggle 竞赛 [NBME – Score Clinical Patient Notes](https://www.kaggle.com/competitions/nbme-score-clinical-patient-notes)，技术路线参考了公开分享的[竞赛第一名方案](https://www.kaggle.com/competitions/nbme-score-clinical-patient-notes/writeups/ryuichi-currypurin-1st-solution)。

## 项目流程

```text
患者病历 + 临床评分要点
            │
            ▼
    数据合并与标注修正
            │
            ▼
  文本分词与字符—Token 标签对齐
            │
            ▼
   DeBERTa Token 分类模型
            │
            ▼
   Token 概率映射回字符位置
            │
            ▼
    阈值筛选与文本跨度后处理
            │
            ▼
   输出临床证据的字符区间
```

基础模型将临床要点和患者病历共同输入 DeBERTa，把证据抽取转化为 token 分类问题。在此基础上，项目还探索了领域自适应预训练、边界监督、数据增强、伪标签和对抗权重扰动等方法。

## 核心技术挑战与解决思路

### 1. 字符级标注与 Token 级预测之间的对齐

**遇到的问题**

数据集中的答案使用字符起止位置标注，而 DeBERTa 处理的是经过分词后的 token。一个单词可能被拆分为多个子词，因此字符位置与 token 位置不能直接对应。如果映射错误，即使模型找到了正确的语义区域，也可能因为边界偏移而丢分。

**解决方法**

- 使用 tokenizer 的 `offset_mapping` 将字符级标注转换为 token 级训练标签。
- 推理时将 token 概率映射回原始文本的字符位置。
- 对字符概率进行阈值筛选，将连续位置合并为文本跨度。
- 对预测跨度进行空白字符清理，生成符合任务要求的字符区间。
- 在实验模型中增加 **span 内部、起始和结束**三个预测通道，为边界学习提供额外监督。

### 2. 标注数据有限，临床表达方式多样

**遇到的问题**

训练集包含 14,300 条「临床要点—病历」标注样本，但只涉及 1,000 份不同的患者病历。与此同时，临床笔记中存在缩写、非正式书写和同义表达，增加了模型理解文本的难度。

**解决方法**

- 使用不属于有标注训练病历的患者笔记进行**掩码语言模型（MLM）继续预训练**，探索让 DeBERTa 适应临床笔记语料。
- 探索利用未标注数据生成伪标签，增加学生模型训练数据。
- 实现句子删除增强：删除未覆盖标注证据的句子，并同步更新受影响的字符偏移量，避免增强后标签与文本错位。

### 3. 防止训练集与验证集之间的数据泄漏

**遇到的问题**

同一份病历会与多个不同的临床要点配对，形成多条训练记录。如果直接按行随机划分，同一份病历可能同时出现在训练集和验证集中，导致验证结果偏高。

**解决方法**

以患者病历 ID 为分组依据进行交叉验证，确保同一份病历只属于一个 fold。通过汇总各 fold 的袋外预测（Out-of-Fold，OOF），评估模型在未参与对应训练的病历上的表现。

训练过程还保存 fold 级 checkpoint 和日志，以便检查结果并恢复耗时较长的实验。

### 4. 判断复杂训练方法是否真正有效

**遇到的问题**

伪标签和对抗训练等方法可能改善模型泛化，但在文本跨度抽取中，伪标签的边界噪声和训练参数的选择也可能损害效果。仅凭方法复杂度无法判断其价值。

**解决方法**

通过受控消融实验比较不同配置。在本项目报告的实验设置下，句子删除增强带来了小幅提升；测试过的伪标签和对抗权重扰动配置则使验证分数下降。实验结果帮助团队保留有效的设计，并分析复杂方法未产生预期收益的可能原因。

## 实验结果

课程报告中的受控五折实验结果如下：

| 实验配置 | OOF 字符级 Micro F1 |
|---|---:|
| 报告中的最佳配置 | **0.8390** |
| 移除句子删除增强 | 0.8374 |
| Baseline + 伪标签 | 0.8239 |
| 对抗权重扰动，ε = 0.01 | 0.8321 |

上述结果是**交叉验证的袋外分数**，并非 Kaggle 排行榜分数，也不代表系统已经用于真实临床环境。不同方法的结果仅对应项目中测试过的配置。
